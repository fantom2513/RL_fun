# Эволюция машинок: флот, ноутбук-заготовка и эталон

**Дата:** 2026-10-08  
**Статус:** дизайн согласован с пользователем

## 1. Зачем нужен этап

Гоночная среда ([спека](2026-10-08-racing-env-design.md)) умеет одну машинку. Цель этапа — режим «как в видео»: пачка машинок едет одновременно, врезавшиеся «умирают», лучшие дают потомство, и так поколение за поколением.

Ключевое решение пользователя: **сеть и алгоритм отбора пользователь пишет сам**. Библиотека даёт только инфраструктуру, а ноутбук содержит пустые места с пояснениями. Рядом лежит **эталонная реализация** с зафиксированными результатами, чтобы сравнивать с ней собственные эксперименты.

Всё считается на CPU (numpy), без GPU и без новых зависимостей: репозиторий используется и на ноутбуке без видеокарты NVIDIA.

Пояснения, подписи и README пишутся на русском. Python-идентификаторы остаются на английском.

## 2. Что входит

1. **Флот** `RacingFleet`: N машинок на одной трассе, векторизованная физика и лучи на numpy.
2. **Прогон поколения** `run_generation`: оценивает популяцию весов функцией пользователя `forward`, возвращает результаты по каждой машинке.
3. **Отрисовка флота** и **панель нейросети** (`NetworkPanel`): много машинок в одном окне, цветные узлы и связи (зелёный — положительное, красный — отрицательное, толщина — величина).
4. **Эталон** `rl_fun.racing.reference`: MLP на numpy и генетический алгоритм, плюс зафиксированный бенчмарк (кривая обучения и лучшие веса для трассы `oval`, seed 7).
5. **Ноутбук** `notebooks/02_racing/01_evolution.ipynb` с заготовками и пояснениями на русском.

## 3. Что не входит

PyTorch и policy gradient (отдельный будущий этап), столкновения машинок между собой, динамика со сносом, редактор трасс, автоматический подбор гиперпараметров.

## 4. Контракты

### 4.1 Векторные примитивы
- `Track.project_many(points) -> (progress, distance)`, `Track.contains_many(points)`, `Track.progress_delta_many(previous, current)`.
- `cast_rays_many(segments, origins, headings, angles, max_range) -> (N, R)`.
- `KinematicBicycle.step_arrays(x, y, heading, v_long, steer, throttle, dt) -> (x, y, heading, v_long, yaw_rate)` для массивов `(N,)`. Результаты совпадают со скалярным `step`.

### 4.2 Флот
`RacingFleet(n_cars, track="oval", dynamics="kinematic", ray_angles_deg=(-90, -30, 0, 30, 90), ray_range=40.0, dt=1/30, max_steps=1500, laps=1)`.

- `reset() -> obs (N, R+3)`; `step(actions (N, 2)) -> (obs, rewards)`. Действия обрезаются до `[-1, 1]`; неверная форма — `ValueError`.
- Наблюдение и награда считаются так же, как в `RacingEnv`: для `n_cars=1` результаты совпадают.
- Атрибуты: `alive`, `finished`, `progress` (в кругах, накопительно), `steps_alive`, `lap_steps` (число шагов до круга или `nan`), `x`, `y`, `heading`, `distances`, `done`.
- Машинка умирает при выезде за границу и останавливается при завершении круга. Мёртвые и финишировавшие не обновляются и не получают награду.
- `done` — когда нет живых машинок или исчерпан `max_steps`.

### 4.3 Прогон поколения
`run_generation(fleet, population, forward, *, view=None, inspect=None, label="") -> GenerationResult`.

- `population` — массив `(N, W)`, строка на машинку; число строк должно совпадать с `fleet.n_cars` (иначе `ValueError`).
- `forward(weights, observation) -> action (2,)` — функция пользователя, вызывается только для живых машинок.
- `GenerationResult`: `progress`, `finished`, `steps_alive`, `lap_steps` (массивы `(N,)`), свойство `best_index`.
- Фитнес по умолчанию — `progress`; пользователь может заменить его в ноутбуке.
- `inspect(weights, observation) -> (matrices, activations)` необязательна и нужна только панели сети.
- Закрытие окна поднимает `ViewClosed`.

### 4.4 Отрисовка
- `Renderer.draw_fleet(...)` рисует N машинок (мёртвые приглушены, лидер выделен, лучи только у лидера).
- `NetworkPanel(input_labels, output_labels, width)` реализует `SidePanel`; `update(matrices, activations)` задаёт состояние.
- `FleetView(fleet, mode="human"|"rgb_array", show_network=True)` собирает рендерер и панель; в режиме `rgb_array` возвращает кадры (для тестов), без окна.

### 4.5 Эталон
- `rl_fun.racing.reference`: `EvolutionParams`, `layer_sizes`, `weight_count`, `init_population`, `forward`, `inspect`, `next_generation`, `train(...) -> ReferenceRun`.
- Бенчмарк `src/rl_fun/racing/benchmarks/oval.json`: параметры, seed, история `[{generation, best, mean, finished}]`, лучшие веса. Генерируется `scripts/make_reference.py`.
- `load_benchmark(track)`, `compare(history, benchmark) -> str` (текстовое сравнение), `plot_comparison(history, benchmark)` (matplotlib, график кривых).
- Эталон воспроизводим: тот же seed даёт ту же историю. Критерий приёмки: эталон проходит круг на `oval` за разумное число поколений.

### 4.6 Ноутбук
Ячейки по порядку: введение, параметры, флот и наблюдения, заготовки `init_population` / `forward` / `next_generation` / `inspect` (с `raise NotImplementedError` и подсказками), цикл обучения, график, сравнение с эталоном, просмотр лучшей машинки, идеи для экспериментов. Эталон импортируется только в ячейках сравнения и просмотра. Окно включается флагом `SHOW_WINDOW`.

## 5. Ошибки

Неверные формы массивов, несовпадение размера популяции и числа машинок, неизвестный бенчмарк для трассы дают понятный `ValueError`. Заготовки в ноутбуке падают с `NotImplementedError` и русским пояснением, что нужно вписать.

## 6. Тестирование

TDD, красные тесты отдельным коммитом. Покрываются: эквивалентность векторных и скалярных функций; поведение флота (смерть, финиш, заморозка, совпадение с `RacingEnv` для N=1); прогон поколения (вызовы `forward` только для живых, ошибки форм); отрисовка флота и панели под dummy-драйвером; обучаемость эталона на малой популяции; воспроизводимость и целостность бенчмарка; структура ноутбука (заготовки на месте и не содержат решения, пояснения на русском, эталон не импортируется вне ячеек сравнения) и выполнение ноутбука с подставленным эталоном без окна.
