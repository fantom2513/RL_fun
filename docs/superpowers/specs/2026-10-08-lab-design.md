# Лаборатория машинок: сервер и веб-интерфейс

**Дата:** 2026-10-08  
**Статус:** макет экранов и порядок согласованы с пользователем; письменная спека готова к ревью

## 1. Зачем нужен этап

Пользователь хочет «играть» с моделью, как в AI Learns To Drive: собирать сеть (входы, выходы, слои), менять награду и параметры эволюции и сразу видеть эффект, при этом запуская несколько конфигураций одновременно и сравнивая кривые обучения. Библиотека уже умеет флот машинок, `ModelSpec`, составной фитнес и эталонную эволюцию; не хватает интерфейса. Этап добавляет локальное веб-приложение «Лаборатория». Редактор трассы (рисование мышью) — следующий этап, отдельная спека.

Все вычисления на CPU, новых Python-зависимостей нет (сервер на стандартной библиотеке), фронтенд без сборки и без npm. Интерфейс и подписи на русском.

## 2. Что входит

1. Пакет `rl_fun.lab`: `RunConfig`, воркер запуска (отдельный процесс), менеджер запусков, HTTP-сервер со статикой, JSON API и потоком событий (SSE), скрипт `scripts/lab.py`.
2. Веб-интерфейс (`rl_fun/lab/web/`, ES-модули, canvas/SVG): вкладки запусков, форма параметров, трасса с машинками и камерой, граф сети лидера, кривые обучения всех запусков.
3. Несколько запусков параллельно (по процессу на запуск), управление: пауза, продолжить, скорость, остановка, «горячее» изменение части параметров.
4. Артефакты каждого запуска в `runs/lab/…` (конфиг, история поколений, лучшие веса).

## 3. Что не входит

Редактор трассы; редактирование сети кликами по графу (в первой версии модель правится формой, граф только показывает сеть); второй обучатель (policy gradient); сохранение и загрузка чужих сетей; динамика со сносом, поверхности трека; аутентификация (сервер слушает только `127.0.0.1`).

## 4. Архитектура

```
браузер ──HTTP/SSE──▶ server.py ──▶ manager.py ──Pipe──▶ процесс worker.py (на запуск)
 canvas, формы        статика, API    потоки-читатели       RacingFleet + reference-эволюция
```

- **Воркер** — `multiprocessing` с контекстом `spawn`. Принимает `RunConfig` (словарь), создаёт `RacingFleet`, популяцию и крутит поколения через `run_generation` с `StreamView` (реализует `draw(fleet, lines, network)`): `StreamView` держит темп, отправляет кадры, опрашивает команды. Выбор родителей, мутация, активации и `inspect` — из `rl_fun.racing.reference`.
- **Менеджер** хранит запуски, по потоку-читателю на запуск; для каждого — последний кадр, историю поколений, статус и условие ожидания для SSE. Медленный клиент получает только последний кадр.
- **Сервер** — `ThreadingHTTPServer`, только `127.0.0.1`, проверка заголовка `Host`, ограничение размера тела (1 МБ), отдача статических файлов только из `web/` (защита от выхода из каталога), ответы JSON в UTF-8.

## 5. Контракты

### 5.1 `RunConfig` (`rl_fun/lab/config.py`)
Замороженный dataclass: `name="run"`, `track="circuit"`, `model: ModelSpec`, `fitness: FitnessSpec` (умолчание — профиль `balanced`), `population=60`, `elite=6`, `mutation_rate=0.15`, `mutation_scale=0.3`, `init_scale=1.0`, `max_steps=1500`, `ray_range=40.0`, `generations: int | None = None` (до остановки), `seed=7`. `to_dict` / `from_dict` (неизвестные ключи — `ValueError`). Проверки: `population` 2…200; `elite` 1…`population − 1`; `mutation_rate` в (0, 1]; `mutation_scale`, `init_scale`, `ray_range` > 0; `max_steps` 50…5000; `generations` ≥ 1 или `None`; `name` непустое, ≤ 40 символов; трасса существует (встроенная или из каталога пользовательских трасс). Все ошибки — `ValueError` с понятным русским текстом для интерфейса.

### 5.2 Протокол сообщений воркера (JSON-совместимые словари)
- `{"t": "frame", "gen", "step", "alive", "n", "cars": [[x, y, heading, state], …], "leader", "rays": [[x, y], …], "net": {"matrices": [...], "activations": [...]} | null, "hud": {"speed", "progress"}}` — `state`: 0 разбита, 1 жива, 2 финишировала; числа округлены до 2 знаков.
- `{"t": "gen", "gen", "best", "mean", "finished", "best_fitness", "best_lap_steps" | null}` — по одному на поколение.
- `{"t": "status", "status": "running" | "paused" | "finished" | "stopped" | "error", "message"?}`.

### 5.3 Команды воркеру
`{"cmd": "pause" | "resume" | "stop"}`, `{"cmd": "speed", "value": 1 | 2 | 4 | 8 | "max"}`, `{"cmd": "update", "params": {...}}` — разрешены только `mutation_rate`, `mutation_scale`, `elite`, `fitness` (словарь весов); применяется со следующего поколения; недопустимое значение отвергается с сообщением, запуск продолжается.

### 5.4 HTTP API
| Метод и путь | Назначение |
|---|---|
| `GET /` и `/static/…` | интерфейс |
| `GET /api/catalog` | входы, выходы, активации, слагаемые и профили фитнеса, умолчания `RunConfig`, список трасс, стиль (палитра и полигоны машинки из `style.py`) |
| `GET /api/tracks/<имя>` | геометрия: ширина, длина, осевая, левая и правая границы, диапазоны бордюров, стартовая поза |
| `POST /api/runs` | создать и запустить (тело — `RunConfig` как словарь); `201` с `{"id": …}`; ошибка валидации — `400` с `{"error": …}` |
| `GET /api/runs` | список: id, имя, статус, поколение, лучший результат |
| `GET /api/runs/<id>` | конфиг, статус, история поколений |
| `POST /api/runs/<id>/command` | команда из 5.3; `404` для неизвестного запуска, `400` для неверной команды |
| `DELETE /api/runs/<id>` | остановить и убрать из списка |
| `GET /api/runs/<id>/stream` | SSE: сообщения 5.2 (`event: frame` / `gen` / `status`); сначала приходят история и последний кадр |

### 5.5 Артефакты
`runs/lab/<имя>-<время>/config.json`, `history.jsonl` (по строке на поколение), `best_weights.json` (лучшие веса за всё время и размеры слоёв), обновляются после каждого поколения.

### 5.6 Интерфейс
Экран «Лаборатория» (согласованный макет): сверху вкладки запусков, «+ новый запуск», пауза/продолжить, скорость (×1, ×2, ×4, ×8, макс), остановка; слева параметры (трасса, популяция, мутация, лимит шагов, награда, входы флажками, углы лучей, скрытые слои списком с `+`/`−`, выходы флажками, активация); в центре трасса с машинками, камерой (вписать/следовать) и зумом колесом; справа граф сети лидера с подписями и легендой; снизу кривые обучения всех запусков (лучший, средний, число финишировавших; цвет по запуску). Параметры, которые можно менять на ходу (мутация, число элиты, веса награды, скорость), редактируются у работающего запуска; структура модели и размер популяции задаются при создании. Окно масштабируется, макет адаптивен. Машинки рисуются векторно (полигоны из каталога стиля), разбитые отмечаются крестом, лидер выделен.

## 6. Ошибки и устойчивость

Падение воркера переводит запуск в `error` с сообщением, остальные запуски не затрагиваются. Закрытие сервера останавливает все процессы воркеров. Неверный JSON, лишние поля и неправильные значения — `400` с текстом. Отключение клиента SSE не влияет на запуск.

## 7. Тестирование

TDD, красные тесты отдельным коммитом. Python: `RunConfig` (валидация, сериализация); построение сообщений (форма, округление, состояния); `StreamView` (темп, пауза, остановка, команды); воркер на маленькой конфигурации в процессе с поддельным каналом (поколения, статистика, остановка, артефакты, `update`); менеджер с настоящим процессом (жизненный цикл, ошибка воркера, остановка при закрытии); сервер по настоящему HTTP на свободном порту (каталог, трассы, создание запуска и ошибки валидации, поток SSE с кадром и поколением, команды, защита путей и `Host`). Фронтенд проверяется в браузере: открывается страница, создаётся запуск, видны кадры, сеть и кривые, масштабирование окна. Запуск сервера для такой проверки выполняется только с разрешения пользователя.
