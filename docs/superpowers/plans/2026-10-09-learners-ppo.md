# Обучатели и PPO: дизайн и план реализации

**Дата:** 2026-10-09  
**Статус:** итерация 2 из `2026-10-08-lab-iterations.md` (пункты S10, S11), бэкенд; интерфейс обучателей делается позже по дизайну из `docs/design/lab-ui/`

## 1. Цель

Добавить в лабораторию встроенный **RL-обучатель PPO** (policy gradient) рядом с эволюцией, без написания кода пользователем и с параметрами, правимыми руками в интерфейсе. Обучатель — подключаемая сущность: интерфейс строится по описанию параметров из каталога, поэтому новые обучатели добавляются без правок интерфейса, кроме их описания.

Все вычисления на CPU. Зависимость `torch` разрешена пользователем (CPU-сборка, явный индекс `https://download.pytorch.org/whl/cpu` в `pyproject.toml`, чтобы на машинах без NVIDIA не тянулись CUDA-колёса). `torch` импортируется только внутри PPO, обычные запуски эволюции его не загружают.

## 2. Архитектура

```
worker.py ──▶ Learner (протокол) ──▶ EvolutionLearner (прежняя логика, вынесена)
                                  └─▶ PPOLearner (новый)
                  │
                  └─ общие: RacingFleet, StreamView, смесь наград, артефакты, сообщения gen/frame/status
```

- `rl_fun/learners/base.py`: протокол `Learner` — `setup(config, fleet, rng, view)`, `run_iteration(iteration) -> IterationResult` (внутри гоняет симуляцию, отдаёт кадры через `view`), `apply_update(params) -> list[str]` (применяет «горячие» параметры, возвращает замечания), `best_snapshot() -> dict | None` (веса в формате `best_weights.json`), `schema()` (описание параметров для каталога).
- `IterationResult`: поля для сообщения `gen` — `best`, `mean`, `finished`, `best_fitness`, `best_lap_steps`, `extra` (словарь числовых метрик обучателя: у PPO `policy_loss`, `value_loss`, `entropy`, `std`, `kl`, `mean_return`, `episodes`).
- Ось X в интерфейсе называется «итерация»: у эволюции это поколение, у PPO — один цикл «сбор опыта + обновление».
- Общий формат весов (`best_weights.json`): плоский вектор в раскладке `rl_fun.racing.reference` (на слой матрица `(out, in)`, затем смещения) и активация модели. Так демо лучшей сети и граф работают для любого обучателя одним кодом.

## 3. Конфигурация

`RunConfig` получает `learner: str = "evolution"` (допустимо `"evolution"`, `"ppo"`) и `ppo: PPOParams`. Прежние плоские поля эволюции (`population`, `elite`, `mutation_rate`, `mutation_scale`, `init_scale`) остаются и действуют только для эволюции; `population` для PPO — число параллельных машинок. Смесь наград (`fitness`) общая.

`PPOParams` (замороженный dataclass, проверки, `to_dict`/`from_dict`): `learning_rate=3e-4` (>0), `gamma=0.99` ([0,1)), `gae_lambda=0.95` ([0,1]), `clip_epsilon=0.2` ((0,1)), `entropy_coef=0.005` (≥0), `value_coef=0.5` (≥0), `rollout_steps=128` (16…1024, шагов на машинку), `epochs=4` (1…20), `minibatch_size=256` (16…8192), `initial_std=0.6` ((0.05, 2]), `max_grad_norm=0.5` (>0), `crash_penalty=1.0` (≥0). Окончательные значения по умолчанию подбираются по результатам обучения (раздел 7) и фиксируются в схеме.

## 4. Награда на шаг (общая для PPO)

`rl_fun/learners/rewards.py`: `StepReward.from_fitness(fitness, dt, max_steps, crash_penalty)`; `compute(fleet) -> ndarray (N,)` после `fleet.step` для всех машинок, бывших живыми на шаге. Слагаемые профиля наград переводятся в «за шаг»:
- `progress`: `Δпрогресса` (в кругах) × 10 (круг ≈ 10 единиц);
- `speed`: `v/v_max × dt × 0.1`; `centering`: `(1 − |смещение|/полуширина) × dt × 0.1`; `smoothness`: `(1 − |Δруля|/2) × dt × 0.1`; `survival`: `dt × 0.1` за каждый живой шаг;
- `lap_bonus`: при финише `(1 − шаги/max_steps) × 5`;
- умноженные на веса профиля; плюс **штраф за аварию** `−crash_penalty` в шаге аварии (параметр PPO, не часть профиля).
Масштабы — константы модуля; при подборе параметров разрешено их менять, фиксируя в документе.

## 5. Флот: расширения под RL

В `RacingFleet`: `respawn(mask)` — вернуть выбранные машинки на старт (состояние, счётчики, статистики, флаги, `steps_alive`) не трогая остальные; публичные массивы последнего шага: `lateral_offset` `(N,)`, `steer_change` `(N,)`, `just_crashed`, `just_finished` `(N,)` bool. Поведение прежнего API не меняется.

## 6. PPO

`rl_fun/learners/ppo.py` (`torch`, CPU, `torch.set_num_threads(1)`):
- **Политика:** MLP по `ModelSpec` (те же слои и активация), выход — `tanh`-среднее; логарифм σ — обучаемый вектор, не зависящий от состояния, начальное значение из `initial_std`. Действие `mean + σ·ε`, в флот идёт с обрезкой в `[-1, 1]`, логвероятность считается для необрезанного.
- **Функция ценности:** отдельная MLP с теми же скрытыми слоями, выход 1.
- **Сбор опыта:** `rollout_steps` шагов для всех N машинок; погибшая или финишировавшая машинка получает терминальный флаг и сразу `respawn`; эпизод длиннее `max_steps` обрывается без терминала (бутстрэп по `V`); кадры уходят в `view` на каждом шаге (темп задаёт `StreamView`).
- **Обновление:** GAE(γ, λ), нормировка преимуществ по батчу, `epochs` проходов по перемешанным мини-батчам, потеря = clip-потеря политики + `value_coef`·MSE(V) − `entropy_coef`·энтропия, Adam (`learning_rate`), обрезка градиента.
- **Метрики итерации:** по завершённым за итерацию эпизодам — `best` и `mean` прогресс (в кругах), `finished`, `best_lap_steps`, `best_fitness` (лучшая сумма награды эпизода), `extra` — `policy_loss`, `value_loss`, `entropy`, `std`, `kl`, `mean_return`, `episodes`.
- **Горячие параметры:** `learning_rate`, `entropy_coef`, `clip_epsilon`, `gamma`, `gae_lambda`, `value_coef`, `crash_penalty`, веса награды; структурные (`rollout_steps`, `epochs`, `minibatch_size`, `initial_std`, `max_grad_norm`, модель, популяция) — только при создании. `update` принимает вложенный словарь `{"ppo": {...}}`.
- **Лучший снимок:** итерация с лучшим скользящим средним `mean_return` (по последним 5 итерациям); веса политики (среднее) экспортируются в общий формат (раздел 2), чтобы `reference.forward` воспроизводил её детерминированное поведение.
- **Граф сети лидера:** активации среднего политики лидера через экспорт весов и `reference.inspect`.

## 7. Каталог и схемы параметров

`GET /api/catalog` получает `learners`: список `{id, label, description, groups: [{label, params: [{key, label, type ("int"|"float"|"choice"), min, max, step, default, log (bool), live (bool), hint}]}]}`; `key` — путь поля в `RunConfig` (`elite`, `ppo.learning_rate`). Для эволюции схема описывает существующие параметры (`population`, `elite`, `mutation_rate`, `mutation_scale`, `max_steps` — как сейчас), для PPO — раздел 3. Интерфейс строит форму по этой схеме.

## 8. Критерий качества обучения

Скрипт `scripts/ppo_check.py` (не тест; запускать вручную) обучает PPO с умолчаниями на `oval` и на `circuit` и печатает кривые. **Приёмка:** на `oval` с настройками по умолчанию за ≤ 5 минут CPU средний прогресс завершённых эпизодов ≥ 0.5 круга, а хотя бы одна машинка финишировала; на `circuit` — рост по сравнению со стартом (круг не обязателен). Если не достигнуто — подбор констант наград и умолчаний (раздел 4, 3) с записью итогов в журнал.

## 9. Задачи

Общие правила: TDD, красные тесты отдельным коммитом (`test: …`), затем реализация (`feat: …`), ruff чист, весь прежний набор зелёный, в коммит только свои файлы, трейлер `Co-Authored-By`; цели тестов указаны перечнем.

### Задача A: Расширения флота
Тесты (`tests/racing/test_fleet_rl.py`): `respawn(mask)` возвращает только выбранные машинки на старт (позиция равна стартовой, `alive=True`, `finished=False`, `progress=0`, `steps_alive=0`, статистики обнулены), остальные не меняются; повторная симуляция после `respawn` совпадает с поведением новой машинки; `just_crashed`/`just_finished` истинны ровно на шаге аварии/финиша и ложны на следующем; `lateral_offset` ≈ 0 на осевой и растёт при отклонении; `steer_change` равен модулю разницы рулей; пустая и полная маски; маска неверной формы → `ValueError`.

### Задача B: Награда на шаг
Тесты (`tests/learners/test_rewards.py`): каждое слагаемое отдельно на искусственном флоте (прогресс прибавляется при движении вперёд, отрицателен назад; скорость, центрирование, плавность, выживание; бонус круга на шаге финиша; штраф на шаге аварии); нулевой вес отключает слагаемое; мёртвые машинки получают 0; масштабы совпадают с разделом 4; сумма наград эпизода близка к ожидаемой для движения по прямой.

### Задача C: Абстракция обучателей, конфиг, схемы
Тесты: `PPOParams` (умолчания, границы, сериализация, русские ошибки с именем поля); `RunConfig` с `learner` и `ppo` (round-trip, неизвестный обучатель → `ValueError`, прежние тесты зелёные); схема каталога (`learners` есть, ключи `key` существуют в `RunConfig`, `default` равен значению по умолчанию, `min ≤ default ≤ max`, у эволюции и PPO заполнены `live`); `EvolutionLearner` через воркер воспроизводит прежние результаты (тесты `test_worker.py` не меняются и зелёные, для одного seed `best` по поколениям идентичен прежнему).
Реализация: вынести логику эволюции из `worker.py` в `EvolutionLearner`; воркер крутит итерации обучателя; сообщение `gen` получает необязательное поле `extra`; `update` разбирается обучателем.

### Задача D: PPO
Добавить `torch` (CPU) в `pyproject.toml` с явным индексом; `uv sync --all-groups`. Тесты (`tests/learners/test_ppo.py`): GAE на маленьком примере с известным ответом (в том числе терминал и обрыв по времени); clip-потеря не увеличивается вне зоны клипа (проверка знаков и нулевого градиента); при синтетическом батче, где преимущество положительно коррелирует с действием, среднее действие сдвигается в нужную сторону после обновления; форма и границы выхода политики; экспорт плоских весов даёт тот же детерминированный выход, что `reference.forward`; детерминизм при одном seed; `respawn` вызывается для погибших; горячие параметры применяются, структурные отвергаются с сообщением; итерация на маленькой конфигурации (6 машинок, `rollout_steps=16`) отрабатывает и возвращает метрики; загрузка модуля не импортирует `torch` до создания `PPOLearner` (проверка через `sys.modules` в подпроцессе или с очисткой).

### Задача E: Воркер, каталог, документы
Тесты: воркер с `learner="ppo"` на 2 итерации (маленькая конфигурация): типы сообщений, два `gen` с `extra`, кадры с `net`, артефакты `best_weights.json` (формат общий, длина совпадает с `model.weight_count`), статус `finished`; `update` с `{"ppo": {"learning_rate": 0.001}}` отражается в следующем `gen`; недопустимый ключ — `notice`; остановка работает; менеджер запускает процесс PPO (интеграционный тест с настоящим процессом, маленькая конфигурация); `/api/catalog` содержит `learners`. Документы: README (раздел лаборатории и PPO), `scripts/ppo_check.py`, запись в журнал итераций с кривыми и итоговыми умолчаниями.
