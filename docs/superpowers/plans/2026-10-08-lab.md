# Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальное веб-приложение «Лаборатория»: параллельные запуски эволюции с настраиваемой моделью, живая трасса, граф сети лидера и кривые обучения.

**Architecture:** `rl_fun.lab`: `RunConfig` → `worker` (процесс `spawn`, крутит `run_generation` с `StreamView`) → `manager` (процессы, потоки-читатели, буферы) → `server` (stdlib HTTP + SSE, статика) → браузерный интерфейс на ES-модулях (canvas/SVG). Спека: `docs/superpowers/specs/2026-10-08-lab-design.md` (разделы 4–5 содержат точные контракты и протокол).

**Tech Stack:** Python 3.12 (stdlib `http.server`, `multiprocessing`, `threading`), numpy, pytest, ruff, uv; фронтенд — чистый JavaScript (ES-модули), canvas, SVG, без npm и сборки. **Новых зависимостей нет.**

**Формат плана:** вместо полного кода даны точные контракты и перечни тестовых случаев с проверяемыми утверждениями; исполнитель пишет тесты и реализацию сам (TDD, красные тесты отдельным коммитом). Если случай теста кажется неверным — остановиться и сообщить, не менять молча.

**Conventions:** TDD; Conventional Commits; AAA; аннотации типов; ruff (line-length 100); ветка `feat/racing-env`; в каждый коммит только свои файлы (`git add <пути>`). Трейлер коммита: пустая строка и `Co-Authored-By: <модель исполнителя> <noreply@anthropic.com>`. Команды из `D:\projects\RL_fun` (PowerShell). Не трогать `docs/reference/`. Весь прежний набор тестов остаётся зелёным. Запуск долгоживущих процессов (сервер лаборатории в браузере) — **только с явного разрешения пользователя**; тесты поднимают сервер на свободном порту внутри процесса pytest и закрывают его по завершении. Windows: воркер запускается с `multiprocessing.get_context("spawn")`, целевая функция должна быть импортируемой на уровне модуля.

### Task 2: Сообщения и `StreamView`

**Files:** `src/rl_fun/lab/protocol.py`, `src/rl_fun/lab/stream_view.py`, `tests/lab/test_protocol.py`, `tests/lab/test_stream_view.py`.

`protocol.py`:
- `build_frame(fleet, generation, network=None) -> dict` по спеке 5.2 (`t="frame"`): `gen`, `step` (`fleet.steps`), `alive` (число живых), `n`, `cars` (`[x, y, heading, state]`, округление 2 знака), `leader` (индекс живой машинки с наибольшим прогрессом, иначе наибольшего прогресса), `rays` — концы лучей лидера `[[x, y], …]` (по `fleet.distances` и `fleet.ray_angles`), `net` (`{"matrices": [...], "activations": [...]}` списками чисел или `None`), `hud` (`speed` лидера в м/с, `progress` лидера в долях круга).
- `build_gen_message(generation, result, scores, params) -> dict` (`t="gen"`): `gen`, `best` (максимум прогресса), `mean`, `finished` (число), `best_fitness` (максимум `scores`), `best_lap_steps` (минимум по финишировавшим или `None`), `params` (эхо `mutation_rate`, `mutation_scale`, `elite`).
- `status_message(status, message=None)`, `notice_message(text)` (`t="notice"`).
- Все значения — обычные `int`/`float`/`list`/`str`/`None` (не numpy); проверка `json.dumps`.

Тестовые случаи `test_protocol.py`: сборка кадра на флоте из 5 машинок после нескольких шагов (ключи, длины, округление до 2 знаков, состояния 1 для живых, 0 для разбитых — довести одну до аварии движением прямо, 2 для финишировавших — выставить `fleet._travelled`), `leader` указывает на живого лидера, `rays` длины `len(fleet.ray_angles)`, `net=None` и `net` с матрицами; `json.dumps` проходит; сообщение `gen` на искусственном `GenerationResult` (best/mean/finished/lap_steps, `None` без финишировавших, эхо параметров); `status`/`notice`.

`stream_view.py`:
- `class StopRun(Exception)`.
- `StreamView(send, poll, *, fps=30.0, dt=1/30, clock=time.monotonic, sleep=time.sleep, speed="max")`: `send(message)` отправляет сообщение, `poll()` возвращает список ожидающих команд (словари) без блокировки. Метод `draw(fleet, lines, network)` (контракт `run_generation`): опрашивает команды (`pause`/`resume`/`stop`/`speed`/`update`), отправляет кадр, если с прошлой отправки прошло не меньше `1/fps`; при конечной скорости (`1`, `2`, `4`, `8`) притормаживает так, чтобы шаг симуляции занимал `dt / speed` реального времени; при `"max"` не спит; на паузе в цикле `sleep` опрашивает команды (кадр на паузе повторно отправляется не чаще `fps`), `stop` поднимает `StopRun` (и во время паузы тоже); команды `update` складываются в `view.pending_updates` (список), забирает воркер; атрибут `current_generation` задаёт номер для кадров.

Тестовые случаи `test_stream_view.py` (поддельные `clock`, `sleep`, `send`, `poll` — без реального времени): частота отправки (30 шагов за 1 секунду фальшивого времени при `fps=10` → около 10 кадров); `speed="max"` не вызывает `sleep`; `speed=1` вызывает `sleep` суммарно ≈ `dt` на шаг; команда `speed` меняет темп; `pause` блокирует до `resume` (поддельный `poll` выдаёт `resume` на третьем опросе), `stop` из обычного состояния и из паузы поднимает `StopRun`; `update` попадает в `pending_updates`; кадры содержат `net`, если передан `network`.

- [ ] Красные тесты → коммит `test: specify lab protocol and stream view`; реализация → коммит `feat: add lab protocol and stream view`.

### Task 3: Воркер

**Files:** `src/rl_fun/lab/worker.py`, `tests/lab/test_worker.py`.

`run_worker(config: dict, conn, runs_dir: str | Path, *, speed="max", clock=..., sleep=...) -> None` — точка входа процесса; `conn` — любой объект с `send(msg)` и `poll(timeout=0)`/`recv()` (канал `multiprocessing.Connection` или подделка). Алгоритм:
1. `cfg = RunConfig.from_dict(config)`; создать каталог артефактов `runs_dir/<name>-<YYYYmmdd-HHMMSS>` (если уже существует — добавить счётчик), записать `config.json`.
2. `RacingFleet(cfg.population, track=cfg.track, model=cfg.model, max_steps=cfg.max_steps, ray_range=cfg.ray_range)`; `rng = default_rng(cfg.seed)`; `sizes = cfg.model.layer_sizes`; популяция `reference.init_population(rng, population, sizes, cfg.init_scale)`.
3. Цикл `generation = 0, 1, …` (до `cfg.generations`, иначе бесконечно): `StreamView` с `forward = lambda w, o: reference.forward(w, o, sizes, cfg.model.activation)`, `inspect` аналогично; `run_generation(fleet, population, forward, view=view, inspect=inspect, label=…)`; `scores = fitness.score(result)`; отправить `gen`-сообщение; дописать строку в `history.jsonl`; обновить `best_weights.json` (`{"sizes", "activation", "weights", "generation", "fitness"}`, лучшее за всё время по `scores`); применить `view.pending_updates` (допустимые `mutation_rate`, `mutation_scale`, `elite`, `fitness`; для недопустимых — `notice` с причиной и без остановки); `population = reference.next_generation(population, scores, rng, EvolutionParams(population=…, elite=…, mutation_rate=…, mutation_scale=…))`.
4. Статусы: `running` в начале, `paused`/`running` при паузе и продолжении (их шлёт `StreamView` или воркер по командам), `finished` по достижении `generations`, `stopped` по `StopRun`, `error` с текстом исключения при любой другой ошибке (исключение наружу не выбрасывается). Между поколениями тоже опрашивать команды (`stop`, `update`, `speed`), чтобы команды не терялись.
5. Тип `InspectResult`: `reference.inspect` возвращает матрицы и активации для `network`; передавать в `build_frame` как `net`.

Тестовые случаи `test_worker.py` (поддельный `conn`, список отправленных сообщений, маленькая конфигурация: `track="oval"`, `population=8`, `elite=2`, `max_steps=60`, `generations=2`, `speed="max"`): 
- последовательность типов: первое сообщение `status running`, затем `frame`/`gen`, два `gen` с номерами 0 и 1, последнее `status finished`;
- хотя бы один `frame` с `net` не `None`;
- артефакты: `config.json` совпадает с `RunConfig.to_dict()`, `history.jsonl` из двух строк, `best_weights.json` содержит `sizes == layer_sizes`, `len(weights) == model.weight_count`;
- команда `stop` (поддельный `poll` выдаёт её сразу после первого кадра) → последний статус `stopped`, артефакты не повреждены;
- команда `update` `{"mutation_rate": 0.5, "elite": 3}` до конца поколения 0 → `gen` поколения 1 содержит эхо `mutation_rate == 0.5`, `elite == 3`; недопустимая `update` (`{"elite": 99}`) → `notice`, прогон продолжается;
- ошибка: конфиг с несуществующей трассой → статус `error` с текстом, без исключения;
- модель с выходами `("steer", "accelerate", "brake", "boost")` и входами из каталога отрабатывает 1 поколение;
- воспроизводимость: два запуска с одним `seed` дают одинаковые `best` по поколениям.

- [ ] Красные тесты → коммит `test: specify lab worker`; реализация → коммит `feat: add lab worker`.

### Task 4: Менеджер запусков

**Files:** `src/rl_fun/lab/manager.py`, `tests/lab/test_manager.py`.

`RunManager(runs_dir, *, worker_target=run_worker_entry)`; `run_worker_entry(config, conn, runs_dir)` — модульная функция верхнего уровня-обёртка над `run_worker` (нужна для `spawn`). Методы:
- `create(config: dict) -> str` — валидирует через `RunConfig.from_dict` (ошибка наружу как `ValueError`), запускает процесс через `multiprocessing.get_context("spawn")` с `Pipe()`, поток-читатель складывает сообщения в состояние запуска; возвращает id (`r1`, `r2`, …);
- `list() -> list[dict]` (`id`, `name`, `status`, `gen`, `best`), `get(id) -> dict` (конфиг, статус, история `gen`-сообщений, сообщение об ошибке);
- `command(id, command: dict)` — проверка формы команды (спека 5.3; неверная → `ValueError`, неизвестный запуск → `KeyError`), отправка в канал;
- `delete(id)` — остановить процесс (сначала `stop`, затем `terminate` по таймауту), убрать из списка;
- `subscribe(id, from_index=0)` — итератор событий для SSE: `(kind, payload)`; сначала история поколений и последний кадр, затем новые сообщения; медленный потребитель получает только последний кадр (кадры не копятся); завершается после терминального статуса и отправки его потребителю; `subscribe` не блокирует остальных потребителей (условие ожидания);
- `shutdown()` — остановить и дождаться всех процессов; безопасен при повторном вызове;
- падение процесса воркера без сообщения (EOF канала) → статус `error` с текстом «процесс запуска завершился неожиданно».

Тестовые случаи `test_manager.py` (маленькие конфигурации, настоящие процессы; таймауты ожидания до 90 с с опросом условия, без фиксированных `sleep` дольше 0.1 с):
- создание → через некоторое время статус `finished`, `history` из N записей, `list` показывает запуск, каталог артефактов создан в `runs_dir`;
- два запуска одновременно завершаются оба и независимы (разные `best` при разных `seed` не обязательны — достаточно разных id, обе истории полные);
- запуск с `generations=None`: после первого `gen` команда `pause` → статус `paused`, `resume` → `running`, `stop` → статус `stopped`, процесс завершён (`process.is_alive()` ложно);
- `command` с неверной формой → `ValueError`; неизвестный id → `KeyError`;
- `delete` работающего запуска завершает процесс и убирает его из `list`;
- `worker_target`, который сразу завершается исключением/выходом (подставляется через параметр) → статус `error`;
- `subscribe`: потребитель, подключившийся после первого `gen`, сразу получает историю, затем новые события и терминальный статус;
- `shutdown` завершает все процессы; повторный вызов не падает.

- [ ] Красные тесты → коммит `test: specify lab run manager`; реализация → коммит `feat: add lab run manager`.

### Task 6: Скрипт запуска и README

**Files:** `scripts/lab.py`, `src/rl_fun/lab/cli.py` (логика `main`), `tests/lab/test_cli.py`, `README.md`.
