# Snake Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add manual Snake, DQN/evolution training and human-left/agent-right play to the local laboratory.

**Architecture:** A Python Snake package owns rules, policies and learners. A separate training process publishes bounded events to a Snake manager; the existing server exposes its API and the existing web shell hosts a dedicated screen. Manual and agent playback use the same Python environment.

**Tech Stack:** Python 3.12+, Gymnasium, NumPy, PyTorch, existing HTTP/SSE server and browser ES modules/canvas; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-snake-lab-design.md` (approved).

**Execution:** Native implementation in this session, as requested by the user's global instructions; research may be delegated. Preserve existing user edits.

## Global Constraints

- UI text is Russian. Code and identifiers are English.
- Default board: 16 by 16 cells, configurable from 8 to 32.
- Agent actions are relative: straight, turn left, turn right.
- Both algorithms use an 11-element input, two hidden layers of 64 units and three output values.
- Only one Snake training job is active at a time in the first version.
- Existing loopback, Host validation and request-size protections remain in force.
- No scripted policy is labeled neural; distinguish an untrained network.
- Store Snake artifacts below the configured runs directory; load no arbitrary pickled objects.

## Review Focus

1. Rapid manual turns and input focus: prevent reversal and accidental input while editing controls.
2. Repeated game creation and abandoned browser sessions: bound retained sessions and release replaced ones.
3. Stop/save during long evaluations: cooperate between steps and checkpoint coherent learner state.
4. Checkpoints from another board or algorithm: reject incompatible continuation and unsafe paths.
5. Server restart and training-process crash: reopen completed records and surface failed states without freezing UI.

## Task 4: Process manager, sessions and HTTP/SSE API

**Files:** create `src/rl_fun/snake/worker.py`, `manager.py`, `api.py`; modify `src/rl_fun/lab/server.py`; create `tests/snake/test_manager.py`, `test_api.py`.

**Interfaces:** `SnakeManager(runs_dir)` owns one training process, persisted run records and bounded game sessions; `shutdown()` closes all owned resources. `SnakeSession` owns one or two environments, policy and queued input. `handle_snake_request(handler, method, path)` handles routes under `/api/snake` using the server's existing JSON/body/SSE plumbing.

API contract: GET catalog/state/models; POST train with config and optional resume model ID; POST control with pause/resume/stop/save; GET events; POST games with mode/size/seed/model ID; POST games/{id}/step with requested direction; DELETE games/{id}. HTTP errors are readable Russian messages; reject invalid lifecycle actions.
