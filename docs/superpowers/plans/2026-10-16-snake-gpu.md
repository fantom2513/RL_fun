# Snake GPU training and pretrained 16x16 model: implementation plan

Spec: `docs/superpowers/specs/2026-10-16-snake-gpu-design.md`
Branch: `feat/snake-gpu` (from `origin/feat/racing-env`)

Rules for every task (from the user's global rules): RED first (write failing tests,
run them, show the failure, commit them as `test:`), then GREEN with minimal code
(commit as `feat:`), then REFACTOR with tests green. Never change a test to make it pass
without telling the user. No new dependencies beyond the torch index switch. Tests in
`tests/snake/gpu/`, AAA, one logical assertion each. Run with `uv run pytest tests/snake`.
Long training runs start only after the user confirms.

## Task 1. CUDA torch

- Edit `pyproject.toml`: index `pytorch-cu128` -> `https://download.pytorch.org/whl/cu128`,
  `[tool.uv.sources] torch` points to it.
- `uv lock`, `uv sync`; check `torch.version.cuda` and `torch.cuda.get_device_name(0)`
  report the RTX 5070 and that a small matmul runs on `cuda`.
- Run `uv run pytest -q` to confirm the whole existing suite is still green on the new
  wheel (record the baseline count of passed/failed before the change as well).
- Commit: `chore: switch torch to the CUDA 12.8 build`.
- Done when: CUDA is available and the baseline suite result is unchanged.

## Task 2. Hamiltonian cycle

Files: `src/rl_fun/snake/gpu/__init__.py`, `cycle.py`; `tests/snake/gpu/__init__.py`,
`test_cycle.py`.

Tests (RED): every cell has a unique index in `0..N^2-1`; cells with consecutive
indices are 4-neighbours; the last cell neighbours the first; sizes 8, 12, 16, 20
pass; odd size and size < 4 raise `ValueError`.
GREEN: row-sweep construction (first column as the return lane).

## Task 3. Batched environment dynamics

Files: `gpu/vec_env.py`; `tests/snake/gpu/test_vec_env.py`,
`test_equivalence.py`.

Design points: `body` grid representation from the spec; `step(actions)` returns
`(obs, reward, terminated, truncated, info)` tensors; `info` carries final score,
length and reason for games that just ended; `set_food(food_xy)` test hook;
`reset(mask, mode)`, modes `standard` and `cycle_segment`.

Tests (RED): scripted equivalence against `SnakeEnv` with forced identical food:
straight move, turn, eat and grow, tail cell is free, eating onto the cell the tail
would leave is fatal, wall collision, self collision, win on a tiny custom board (use
`size=8` with a pre-filled snake from `load_state`), starvation truncation, auto-reset;
seed reproducibility; batch of 1000 random-policy games never leaves an invalid state
(length equals count of nonzero body cells, exactly one head, food on a free cell).
GREEN: implement. Commit tests and code separately.

## Task 4. Observation contract and CPU parity

Files: `gpu/vec_env.py` (observation), `src/rl_fun/snake/env.py` (new mode
`egocentric_cycle`, six planes), `config.py` (accept the mode),
`tests/snake/gpu/test_observation.py`, extend `tests/snake/test_env.py`.

Tests (RED): `VecSnake` and `SnakeEnv` observations are exactly equal on 500 random
states per heading; observation space shape `(6, 2N-1, 2N-1)` flattened for the CPU env;
the cycle plane at the head cell is 0 and increases along the cycle direction; action
mask matches `SnakeEnv._danger` for all three moves. Existing modes unchanged (the
current `tests/snake` suite stays green).
GREEN: implement; the CPU env builds the cycle plane from `hamiltonian_cycle`, so
`egocentric_cycle` requires an even board.

## Task 5. Throughput gate

Files: `scripts/snake_gpu_bench.py`.
Runs random-policy steps with observations for 4096 games on 16x16 and prints
steps/s. Gate: >= 100,000 steps/s. If lower: remove host syncs, fuse the observation
gather, try `torch.compile` or CUDA graphs, measure again. Report the number to the user.
Commit: `feat: add the GPU throughput benchmark`.

## Task 6. Teacher

Files: `gpu/teacher.py`; `tests/snake/gpu/test_teacher.py`.

Tests (RED): the pure cycle follower wins every game on 8x8, 12x12 and 16x16 (200,
100, 50 games); the shortcut teacher wins every game on 1000 games (8x8) and 200 games
(16x16); shortcut teacher mean steps per game is below the pure follower's; the teacher
never picks a fatal move; the teacher also wins from cycle-segment starts of every
length class (short, half, 90% of the board).
GREEN: implement the rules from the spec. If the shortcut teacher loses even one game,
tighten the margin or the length limit (document the final values in the spec) before
continuing. This is the first correctness gate for the whole plan.

## Task 7. Model, dataset, cloning

Files: `gpu/model.py`, `gpu/imitation.py`, `gpu/checkpoint.py`;
`tests/snake/gpu/test_model.py`, `test_imitation.py`.

Tests (RED): output shapes `(B,3)` and `(B,)`; deterministic greedy action; checkpoint
round trip with `weights_only=True`; rejects wrong size/plane count/version; dataset
generation yields teacher actions that match a fresh teacher run; a tiny 8x8 cloning
run (few thousand samples, 200 steps) beats 90% action accuracy on its own training
distribution.
GREEN: implement `ConvActorCritic`, teacher-rollout dataset generation (standard and
cycle-segment starts, balanced by game phase), cross-entropy training loop with
accuracy logging, atomic checkpoint save.

## Task 8. GPU evaluation

Files: `gpu/evaluate.py`; `tests/snake/gpu/test_evaluate.py`.
Tests (RED): evaluating the teacher wrapped as a policy gives a 100% win rate; the
evaluator reports wins, occupancy, steps and failure reasons; the same seeds give the
same outcomes; a greedy loop (no progress) is cut off with a `loop` reason by step cap.
GREEN: implement; both backends (`VecSnake`, and `SnakeEnv` for acceptance).

## Task 9. Cloning gate (needs the user's go for the longer run)

Files: `scripts/snake_gpu_train.py` (stage `clone`).
Run 8x8 first (minutes), then 12x12 and 16x16. Report: action accuracy, greedy win
rate and failure reasons on the tuning seeds. If the 8x8 clone is under 50% wins,
stop and diagnose (observation, capacity, data balance) with the user before PPO.
Record the numbers in `docs/snake-research.md`.

## Task 10. PPO fine-tuning

Files: `gpu/ppo.py`; `tests/snake/gpu/test_ppo.py`; stage `finetune` in the script.

Tests (RED): GAE against a hand-computed trajectory including episode boundaries and
truncation bootstrapping; clipped loss is zero when ratios are 1 and advantages are 0;
one update changes parameters and keeps them finite; the critic-only phase leaves the
policy parameters bit-identical; the KL penalty is zero for identical policies; a toy
corridor environment is solved in a few updates.
GREEN: implement with the options from the spec (invalid-move mask in training,
critic warm-up, KL anchor, best-checkpoint on greedy evaluation).
Run on the ladder, first 8x8 and 12x12, then 16x16, with the user's confirmation for
each long run. Gate: win rate on the tuning seeds does not drop below the clone's.
Contingencies, each raised with the user before building: curriculum with arbitrary
long bodies, flood-fill auxiliary head, larger network.

## Task 11. Acceptance on the authoritative environment

Files: `scripts/snake_gpu_verify.py`; `tests/snake/gpu/test_pretrained.py` (skipped when
the checkpoint file is absent).
Load the frozen checkpoint, play 100 games on seeds `3000000..3000099` with the CPU
`SnakeEnv` in `egocentric_cycle` mode, greedy and without mask. Print wins, occupancy,
steps, failure reasons and the `verification_status`. Save the result as JSON next to
the checkpoint. Report the number to the user as it is.

## Order and checkpoints

Tasks 1-5 build the fast environment (stop and report after Task 5: throughput number).
Tasks 6-9 build the teacher and the clone (stop and report after Task 9). Tasks 10-12
are fine-tuning, verification and integration. The user reviews after each stop.
